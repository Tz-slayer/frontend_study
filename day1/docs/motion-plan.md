# Day1 动效方案

## 动效方向

这个页面适合的动效气质，不是“活泼”，而是“仪式感、克制、带一点压迫感”。

动效目标不是让所有元素都动起来，而是通过有节奏的登场顺序，让用户依次注意到：

1. 切片式人物主视觉
2. 皇冠
3. 发光的竖向名字标记

这个页面更适合先完成一次有层次的揭幕，再进入一个非常轻的静态呼吸状态。

## 动效原则

1. 动效的作用是建立视觉层级，不是给每个元素加装饰。
2. 优先使用 `transform` 和 `opacity`。
3. 持续动效必须克制、缓慢、低存在感。
4. 避免可爱感、弹跳感、频闪感和大幅度循环旋转。
5. 页面里只能有一到两个“记忆点动效”，不要让所有元素同时抢戏。

## 动效层级

### 1. 首屏入场动效

这一段只在页面初次加载时执行一次。

#### 内容区幕布揭开

你现在已经有 `.content::after` 的暗色渐层遮罩，这很适合拿来做“幕布”。

建议方式：

- 初始时遮罩略重
- 再缓慢过渡到当前静止状态的透明度
- 时长控制在 `500ms` 到 `800ms`
- 缓动建议用 `ease-out`

作用：

让页面不是直接出现，而是像舞台灯光慢慢亮起。

#### 三个主画面切片依次登场

当前实现里，三块主要切片已经按顺序入场，不是同时出现。

当前顺序：

1. `.frame3` 先出现，作为主纵向骨架
2. `.frame1` 第二个出现
3. `.frame2` 最后出现

当前实现方式：

- 切片本体先以白色实体块显现
- 人物内容不会在 `stage-frame` 里一起出来，而是后续在 `stage-portrait` 阶段统一释放
- 切片本体使用 `opacity + transform` 入场

当前参数：

- 初始态：`opacity: 0`
- 初始态：`transform: translateY(18px) scale(1)`
- 最终态：`opacity: 1`
- 最终态：`transform: translateY(0) scale(1)`
- 延迟顺序：
  `.frame3` `120ms`
  `.frame1` `240ms`
  `.frame2` `360ms`

作用：

先建立切片构图，再把人物内容延后释放，避免角色过早暴露。

#### 皇冠落位

当前实现里，皇冠仍然是人物内容释放前的触发点。

当前实现方式：

- 初始态略高
- 初始角度略小
- 进入 `stage-crown` 后回到最终角度

当前参数：

- 初始态：`opacity: 0`
- 初始态：`transform: translateY(-12px) rotate(-38deg)`
- 最终态：`opacity: 1`
- 最终态：`transform: translateY(0) rotate(-45deg)`
- 过渡：`700ms ease`

作用：

在构图完成后再引入象征元素，让后续人物 reveal 有明确触发点。

#### 名字标记分段显现

现在这组竖向标记已经有一版可运行的顺序动画，当前实现如下。

当前顺序：

1. 上方 `dot` 先恢复到正常大小
2. `line-top` 从上方 `dot` 向下延伸
3. 文字 `span` 出现
4. 下方 `line-bottom` 从下方 `dot` 向上延伸
5. 下方 `dot` 最后补上

当前实现方式：

- 两个 `dot` 使用 `opacity + scale` 显现
- `line-top` 和 `line-bottom` 使用 `scaleY` 显现
- `line-top` 的 `transform-origin` 是 `center top`
- `line-bottom` 的 `transform-origin` 是 `center bottom`
- 文字使用 `opacity + translateY` 显现

当前初始态：

- `.dot`: `opacity: 0; transform: scale(0.6);`
- `.line-top`: `opacity: 0; transform: translateY(-5px) scaleY(0);`
- `.line-bottom`: `opacity: 0; transform: translateY(5px) scaleY(0);`
- `span`: `opacity: 0; transform: translateY(12px);`

当前进入态：

- `.dot`: `opacity: 1; transform: scale(1);`
- `.line-top`: `opacity: 1; transform: translateY(-5px) scaleY(1);`
- `.line-bottom`: `opacity: 1; transform: translateY(5px) scaleY(1);`
- `span`: `opacity: 1; transform: translateY(0);`

当前延迟：

- 上方 `dot`: `60ms`
- `line-top`: `140ms`
- `span`: `260ms`
- `line-bottom`: `380ms`
- 下方 `dot`: `480ms`

当前问题记录：

- 线段虽然已经按上下两端的 `transform-origin` 去延伸，但名字标记整体节奏仍然偏机械
- 上下两端 `dot` 与两条线的因果关系还不够强
- 下方 `dot` 当前是最后补上，这和“线从 dot 中长出来”的感受并不完全一致

作用：

把用户视线从主画面收束到角色名字，但这部分仍然保留继续优化空间。

## 阶段控制方式

这个页面的首屏动效，不建议理解成“所有元素各自动画”，也不建议做成“完全严格串行”的流程。

更合适的方式是：

1. 按阶段推进
2. 阶段之间允许重叠
3. 用统一时间轴控制每个阶段的开始时间

### 为什么不用完全串行

如果强制要求“上一个阶段彻底结束，下一个阶段才能开始”，页面会容易显得机械、拖沓。

这个页面更适合：

- 背景刚接近完成时，主切片开始进入
- 主切片后半段时，辅助切片和装饰线提前接入
- 皇冠和名字标记在构图基本稳定后再补上

这种做法能保留层次感，同时避免节奏太僵。

### 为什么不用纯 CSS `transition-delay`

只靠 `transition-delay` 的问题是：

1. 所有阶段一开始就被写死在一堆延迟里
2. 后面调整一个阶段时，整条时间链都要重算
3. 很难表达“阶段 A 和阶段 B 重叠 150ms”这种设计意图
4. 页面变复杂后维护成本会快速升高

所以更推荐：

- CSS 负责定义每个阶段的目标状态
- JavaScript 负责按时间轴打开对应阶段

### 推荐实现模型

用 `body` 的阶段类来驱动动画，例如：

- `stage-bg`
- `stage-frame`
- `stage-decor`
- `stage-crown`
- `stage-portrait`
- `stage-name`
- `stage-idle`

这些类不是互斥覆盖，而是随着时间推进逐步叠加。

例如：

- 页面开始时只有 `is-preload`
- 到背景阶段时，添加 `stage-bg`
- 到主切片阶段时，再添加 `stage-frame`
- 到装饰阶段时，再添加 `stage-decor`

这样每个阶段只需要负责“打开自己那一层”，不会互相覆盖。

### 阶段重叠的计算方式

如果一个阶段的开始时间、持续时间和希望重叠的时间已经确定，可以这样估算下一个阶段的起点：

`下一个阶段开始时间 = 上一个阶段开始时间 + 上一个阶段时长 - 希望重叠的时间`

例如：

- 背景阶段从 `0ms` 开始
- 背景阶段时长 `800ms`
- 希望和主切片阶段重叠 `150ms`

那么主切片阶段可以在 `650ms` 开始。

## 推荐阶段时间轴

结合当前页面结构，建议使用下面这条时间轴。

### 阶段定义

1. `stage-bg`
   控制 `header`、`content`、`footer` 和 `.content::after` 的渐显
2. `stage-frame`
   控制 `.frame1`、`.frame2`、`.frame3` 的主切片入场
3. `stage-decor`
   控制 `.frame4` 和 `.decorate` 下各根装饰线的进入
4. `stage-crown`
   控制 `.crown` 的落位
5. `stage-portrait`
   控制三块主切片中的人物内容显现
6. `stage-name`
   控制 `.line-container` 内圆点、竖线和文字的显现
7. `stage-idle`
   控制首屏结束后的轻微呼吸动效

### 建议时间表

1. `stage-bg`: `0ms`
2. `stage-frame`: `650ms`
3. `stage-decor`: `1100ms`
4. `stage-crown`: `1700ms`
5. `stage-portrait`: `2050ms`
6. `stage-name`: `2780ms`
7. `stage-idle`: `3280ms`

### 这条时间轴的含义

- 背景先建立空间氛围
- 主切片先以白色切片板进入
- `frame4` 和四角装饰线补全构图
- 皇冠在画面结构稳定后落位
- 人物内容在 `stage-portrait` 里被释放出来
- 名字标记最后作为视觉收束
- 全部完成后才进入静止态呼吸

### 2. 静止态呼吸动效

当首屏入场结束后，页面只保留极轻的持续动效。

不要让所有元素一直动，只保留一到两个低频动作。

#### 发光轻呼吸

可以让这些元素做非常缓慢的亮度呼吸：

- `.dot`
- `.line`
- 角色名字的文字阴影

规则：

- 周期控制在 `3s` 到 `5s`
- 只做小幅度亮度变化
- 严禁做成频闪

作用：

让页面保持生命感，但不制造噪音。

#### 皇冠轻微漂浮

皇冠在完成入场后，可以保留一个非常弱的漂浮动作。

建议方式：

- 上下只移动几像素
- 可以有极轻的角度摆动，但一定要围绕最终角度
- 动效周期至少 `4s` 以上

作用：

让页面停下来之后仍然有一点气场，而不是完全死掉。

## 阶段内部节奏

阶段之间由统一时间轴控制，阶段内部再用少量错峰处理层级。

例如：

1. `stage-frame` 内部：
   `.frame3` 先进入，`.frame1` 第二个，`.frame2` 最后进入
2. `stage-decor` 内部：
   可以先右上角，再左下角；也可以先主横线，再主竖线，再副线
3. `stage-name` 内部：
   先圆点，再竖线，再文字，最后补下半段

## 不建议做的动效

1. 皇冠做大幅度持续旋转。
2. 所有切片一直各自漂浮。
3. 白色发光区域做快速闪烁。
4. 每个切片都做 hover 放大。
5. 同一个元素同时叠很多种不同节奏的动画。

## 实现时的注意点

如果后面真正写代码，建议遵守这些限制：

1. 切片和皇冠尽量只动画 `transform`、`opacity`。
2. `filter` 可以用，但要克制，持续高频变化容易重。
3. 静止态呼吸必须弱于首屏入场。
4. 需要兼顾 `prefers-reduced-motion`，减少或关闭整段揭幕动画。
5. 阶段切换建议由 JavaScript 时间轴驱动，不建议把所有阶段只写进一堆 `transition-delay`。
6. 细粒度装饰线动画应优先使用真实元素和 `scaleX`、`scaleY`，不要继续依赖单个 `background` 图层。

## 判断标准

如果动效是成功的，应该满足这几个结果：

1. 用户先注意到人物切片构图
2. 皇冠像“刻意安排的重点”，不是随手加的装饰
3. 名字标记像一种仪式化符号
4. 页面静止时仍然有气场，但不会显得忙乱
